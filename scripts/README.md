# Research latency benchmark

Run `node scripts/benchmarkResearch.ts` from the repository root with Node 24 or later. The script makes paid OpenAI API requests, Google Places/geocoding requests, and real Codex Cloud research jobs. It does not change the deployed application. Each location runs one API request and one cloud request concurrently; the next location waits for both to finish so the benchmark does not queue its own location pairs behind one another. Empty geographically validated results can expand the search radius through the existing service.

Provide `OPENAI_API_KEY` and `GOOGLE_MAPS_API_KEY` in the process environment. Set `RESEARCH_RUNNER_URL` and `RESEARCH_RUNNER_TOKEN` for another runner; the defaults are the documented Codex Cloud worker and `~/.config/codex-cloud/token`. `CODEX_CLOUD_DIR` defaults to the sibling `../codex-cloud` checkout and supplies the current runner instruction file. The benchmark generates its own temporary ticket secret. It does not need production ticket credentials or load `.env.local`.

An optional first argument selects the output file, for example `node scripts/benchmarkResearch.ts plans/api-latency-repeat.json`. The default is `plans/api-latency-samples.json`; use another filename to preserve an earlier run. Results contain timings, token counts, estimated API costs, story counts, and hashes of the paired prompts. Prompts, Google candidates, generated stories, credentials, and recovery tickets stay out of the report. The initial nearby-place lookup is measured separately and is excluded from each arm's elapsed time.

Set `BENCHMARK_LOCATION` to a matching part of a location label to repeat one pair, for example `BENCHMARK_LOCATION=Paris node scripts/benchmarkResearch.ts plans/api-latency-paris-repeat.json`. Failed arms are recorded with their elapsed time, completed pass metadata, failure stage, and a controlled error code. Raw provider errors are never exported. A failed poll does not cancel its cloud job; inspect the recorded job ID before deciding whether another run is needed.

The API uses Astra at low effort, standard processing, no tools, and streaming. It uses the same textual JSON instructions as the CLI and passes the result through the existing service's schema and geographic validation. The comparison deliberately does not introduce API Structured Outputs or change the editorial prompt. First-text timing is diagnostic; it does not mean a complete, validated story can already be displayed. The API's 6,000-token output ceiling bounds benchmark cost; check that every response completes before comparing results.

API costs use the September 10, 2026 standard Astra rates: $10 per million uncached input tokens, $1 per million cached input tokens, and $50 per million output tokens, including reasoning. These are model-cost estimates, not invoice totals, and exclude Google, hosting, and the Codex subscription. Refresh the constants against the [official model pricing](https://developers.openai.com/api/docs/models/gpt-6-astra) before using the script for future cost comparisons.

The cloud arm keeps the deployed five-second polling interval. Its first observed running time is an upper bound affected by polling; use the runner's `research_timing` queue event for an exact observed queue duration. Capture `research_timing` and `research_trace` through the runner's documented Wrangler tail workflow and correlate job IDs with the report. The API arm completes in memory, so this is a backend-path comparison rather than a measurement of a deployed API integration or the mobile interface.

Verify the diagnostic with `pnpm exec tsc --ignoreConfig --noEmit --target es2023 --module esnext --moduleResolution bundler --allowImportingTsExtensions --skipLibCheck --strict --types node scripts/benchmarkResearch.ts`, `pnpm lint`, and the existing service checks: `pnpm test run server/tests/research.test.ts server/tests/nearby.test.ts`.
